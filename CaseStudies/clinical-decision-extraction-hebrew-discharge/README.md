# Cross-Lingual Clinical Decision Extraction from Synthetic Hebrew Discharge Summaries

- **Paper section:** 3.2.1
- **Source repository:** https://github.com/ori-mor/hebrew-clinical-decision-extraction-final

## Motivation

Hebrew clinical text is mixed-language (Hebrew prose interleaved with English drug names, procedure names, abbreviations, and dosages) and has essentially no open, labeled medical corpus for training or evaluation. This project targets grounded decision-span extraction: given a Hebrew or Hebrew-English discharge summary, extract every clinical decision span as a 4-tuple (`mention_text`, `label`, `canonical_concept`, `canonical_action`), where `mention_text` must be copied verbatim from the source, character-for-character. Because no labeled Hebrew clinical corpus exists, the prerequisite problem was to build a Hebrew dataset grounded in real clinical decisions without redistributing any real Hebrew record.

## Data generation protocol

The data is "source-linked but synthetic". Real English decision annotations from MedDec (derived from MIMIC-III) are used only as grounding for what a valid Hebrew decision target should look like; no MedDec/MIMIC-III text is redistributed in the repository. The pipeline runs in stages:

1. **Seed extraction** — MedDec-derived clinical decisions (drug/procedure decisions with a defined action) are extracted and grouped into a seed pool (`extracted_annotations.jsonl`, `generation_seed_pool.jsonl`, `grouped_seed_records.jsonl`).
2. **Prompt build** — for each seed set of required targets, a generation prompt is assembled combining the clinical targets that must appear, an attribute vector controlling diversity (writer style, text format, length profile, language mix, clinical focus, noise level), and marked-span anchoring (temporary marker tags around each target decision so exact `mention_text` and character offsets can be recovered). See `prompts.py` and `generate_data.py`.
3. **LLM expansion** — Hebrew summaries were generated by **GPT-4o-mini** through three OpenAI Batch API rounds (100 / 150 / 195 tasks), each stratified toward gaps in the pilot data (procedure decisions and rare actions `stop`/`continue`/`change`/`planned`). The pool is closed at 445 submitted tasks, 518 accepted across pilot plus all expansion rounds plus the original manual-generation round.
4. **Validation / grounding** — every accepted example passes structural checks, verbatim grounding (each `mention_text` appears exactly inside `summary_text_he`), concept/action alignment, unsupported-decision rejection, and ambiguity handling. A post-acceptance audit additionally flags semantic contradictions (a disclosed dataset limitation).

Two dataset versions exist: a pilot (v1) used for the interim baseline, and an expanded final (v2) used for the reported model comparison. The v2 held-out test split is 81 summaries / 185 gold decision spans.

## Models trained and evaluated

All models are evaluated on the same v2 test split (81 summaries, 185 gold spans), strict F1 = exact-span match.

- **Qwen few-shot** (`Qwen2.5` few-shot prompting baseline) — generative extraction.
- **XLM-R BIO** — XLM-RoBERTa fine-tuned as a BIO token tagger.
- **sklearn candidate reranker** — LogisticRegression / calibrated LinearSVC over TF-IDF + context features selecting spans from a deterministic high-recall candidate list (CPU-only, no API).
- **Gemini candidate-constrained selector** — `gemini-3.1-flash-lite` structured-output selection over the same style of candidate generator (free-tier, $0).

## Results

Strict (exact-match) and relaxed (any-overlap) F1 on the v2 test split:

| Metric | Qwen few-shot | XLM-R BIO | sklearn reranker | Gemini selector |
|---|---|---|---|---|
| strict drug F1 | 0.209 | 0.248 | 0.164 | **0.270** |
| strict procedure F1 | 0.204 | 0.428 | **0.564** | 0.379 |
| strict overall F1 | 0.206 | 0.326 | **0.427** | 0.318 |
| relaxed overall F1 | 0.650 | 0.829 | 0.677 | **0.926** |

Key findings: the sklearn candidate reranker achieves the highest strict overall F1 (0.427) and strict procedure F1 (0.564). The Gemini selector achieves the highest strict drug F1 (0.270) and the highest relaxed overall F1 (0.926). The Qwen few-shot baseline shows a 20.1% overall not-verbatim (hallucinated span) rate, motivating the verbatim-grounding constraint. Note: Qwen's relaxed metric uses a >=30%-character-overlap threshold while the other three use any-overlap, so Qwen relaxed F1 is not directly comparable on the relaxed row (strict F1 is exact-match and comparable throughout).
